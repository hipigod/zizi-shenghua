### 测试踩过的坑（写新测试时必看）
1. **必须先 `showScreen("#screen-game")`**：未进游戏屏时 `#screen-game` 隐藏，
   `#cardcol` 的 computed display 是 none，`useDrawer()` 判真 → showCard 走抽屉路径，
   测到的不是桌面右侧卡片。这条坑浪费了两轮。
2. **HanziWriter 会先建空 svg 骨架再填数据**，判定笔顺必须用 `svg path` 数量 > 0，
   只查 `svg` 存在会把加载失败的字误判为通过。
3. **`r.stroke === true` 是布尔表达式**，非 true 时直接产出 false 而非原值，
   导致表格里出现莫名其妙的 "✗ false"。要写成 `x === true ? true : x`。
4. **不要用 `--virtual-time-budget` 跑含异步网络等待的测试**：虚拟时钟被快进，
   `Date.now()` 阈值瞬间到达，fetch 还没回来就判定超时。
   改为后台起 Chrome（不加该参数）+ 页面 POST 回 `tools/fulltest_result.json`，
   外层轮询文件出现即可（`serve.py` 已加 `POST /report`）。
5. 注入脚本插入数组末尾时，最后一条没有尾逗号，需先补 `,` 再插入。

## 合成后原料从画布消失，只留合成字

- 用户反馈：合成后两个字还留在画布上，多做几次就堆满「乱七八糟的字卡」。
- 改法（board.js）：原 mergeAnimation 把原料「分列左右」留在原位；现改成
  两块向新字落点汇聚（150ms）→ 一起加 .merging-out 缩小淡出（180ms）→ 新字同位长出。
  画布上每次合成净减 1 块，只剩结果。
- 关键实现：新增 detachTile(t)——只从 tiles 数组摘出、保留 DOM 做淡出。
