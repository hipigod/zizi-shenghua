# 2026-10-27 字字生花

## 新增：画布字块删除的三条入口（用户问「怎么把字块从画布删掉」）
- 现状：只有「拖回库存=回收」一条隐藏路径，无任何可见提示 → 发现度为零，用户找不到很正常
- 设计原则：库存无限、字块不消耗，删除**零成本可逆** → 不需要二次确认，给最顺手的入口即可
- 三条并行入口：
  1. 右键画布字块 = 收回（ui.js contextmenu 优先级：字块 > 卡片）+ toast「已收回「X」，需要时从库存再拖出来」
  2. 拖回库存 = 收回（原有）+ 拖拽悬停库存时 `.recycle-hot` 高亮 + 「🗑 松手就收回」提示条
  3. 「清空画布」按钮（index.html btn-clear，board.clearBoard 已有）批量清，库存不受影响
- board.js 新增导出 removeTileByEl(el)、内部 pointInInventory/setRecycleHot；pointerup/cancel 复位高亮
- 画布右下角加常驻小字提示「拖回左侧库存或右键字块即可收回」（<1180px 隐藏）

## 踩坑
- **inventory 每次 renderInventory 都 `innerHTML=""`**：写在 index.html 里的静态 `.recycle-tip` 会被清掉，
  必须由 JS 在清空后重建（单一来源放 ui.js）。凡是动态重渲染的容器，静态子节点都不可靠
- **playwright 浏览器缓存旧页面**：改了 index.html 后 `open url?x=1` 仍可能拿到旧 DOM，
  必须在 run-code 里 `page.goto(url + Date.now())` 才稳。本次因此误判一次「元素不存在」

## 本地服务器换成 tools/serve.py（根治缓存）
- 旧 `python -m http.server` 不发 Cache-Control，浏览器缓存旧 JS/HTML，已踩三次（board undefined、
  recycle-tip 找不到、改了 HTML 测试拿到旧 DOM）
- 新脚本：ThreadingTCPServer + SimpleHTTPRequestHandler 子类，end_headers 注入
  `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` + Pragma/Expires
- 用法：`python tools/serve.py`（端口用环境变量 ZZSH_PORT 覆盖，默认 8765），工作目录自动切到项目根
- 已验证：响应头含 no-store，index.html/board.js 均 200

## 回归验证（全过）
- 右键字块收回+toast；右键库存字块不动（invCount 不变）；拖回库存收回且高亮提示显示/复位

## 交付前缺陷修复（5 处，全部实测通过）

### 1. 库存拖拽无指针捕获 → 可复现永久死锁（最严重）
- `startInvDrag` 未设 `setPointerCapture`，指针移出窗口或松手在窗口外时
  `pointerup/pointercancel` 到不了 document，`drag` 永久非空 → 首指锁定把后续
  pointerdown 全挡掉，**整个画布再也拖不动，只能刷新**
- 修：库存拖出也设捕获；新增 `abortDrag()`；监听 `lostpointercapture` / `blur` /
  `visibilitychange` 一律按取消处理；再加 `reapStaleDrag()`（20 秒）兜底
- 原则：**drag 宁可空，绝不能残留非空值**

### 2. iOS 视口 `--vh` 是死变量
- `main.js` 设了 `--vh`，但全项目零引用，iPhone 上底部库存条被地址栏吃掉
- 修：`style.css` 的 `.screen` 加 `height: calc(var(--vh, 1vh) * 100)`；
  补 `visualViewport.resize` 监听（iOS 地址栏收缩不一定触发 window resize）

### 3. 字源硬错（语文老师第一眼会看到）
- **问**：原写「口在门中，敲门发问」会意，却标《说文解字》→ 实为**形声：从口门声**
- **因**：原写「《说文》作形声：从囗大声」→ 《说文》实为「因，就也，从囗大」**会意**
- **间**：引《说文》却不说明字形 → 繁体本作「閒」，门内是**月**不是日，简体才改日
- **燚**：四个火标「品字结构」→ 改为「四叠」

### 4. 伪组词（界面会显示「组词：几乎只用于地名」）
- 未「未完/未开」→ 未来/未知/未曾；困「困了」→ 困难/困住/困倦
- 棵「一棵树/几棵草」、焱「多用于书面语」、燚「多用于人名」、沝「几乎只用于地名」
  → 全部清空；`ui.js` 本就有 `words && words.length` 判断，空数组自动隐藏整行

### 5. 字体从未加载却写着「霞鹜文楷」（虚假署名）
- 无 `fonts/` 目录、无 `@font-face` → `--font-kai` 第一个族名永远落空，实际回退系统楷体
- 修：CDN 拉 lxgw-wenkai-lite-webfont 分片 → 合并 → 子集化
  （脚本 `tools/build_font_subset.py`，辅助 `tools/find_subsets.py`）
- 结果：**110 字 / 20.9 KB**（原字体 20MB+），完全符合框架「只含游戏用到的 100 多字」
- 坑：Windows curl(schannel) 下载 release 报 exit 35 SSL 握手失败 → 改用 PowerShell
  `Invoke-WebRequest` 成功；CDN 的 CSS 里 `unicode-range` **没有结尾分号**，正则别要求分号

## 移除右侧卡片列上方的「最近发现」条（用户判定多余）
- 现象：点过「问」的字源卡后，再点别的字，卡片左上角始终留着一个「问」字块，像叠了一层卡
- 根因：`showCard` 桌面分支写的是 `col.innerHTML = recentHTML + html`，
  其中 recentHTML 来自模块级 `recent` 数组（每次合成新字 `pushRecent` 入栈，最多 8 个），
  于是历史点过的字会以 `.tile` 形式常驻在卡片上方
- 修：`$("#cardcol").innerHTML = html`（只渲染当前这一张）；`closeCard` 直接回填 TIP_HTML，
  不再判断是否残留 `.recent-strip`
- 连带清理：删除 `var recent = []`、`pushRecent()` 定义、其唯一调用点（合成成功分支），
  以及 style.css 的 `.recent-strip` / `.recent-items` 四条规则
- 已实测：连点 问→果→林，任何时刻 `#cardcol .char-card` 恒为 1、`.tile` 恒为空
